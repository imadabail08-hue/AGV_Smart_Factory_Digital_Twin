Problème Industriel & Périmètre Technique
Le transport intra-logistique automatisé en environnement partagé constitue un verrou opérationnel majeur dans les usines de nouvelle génération. Les AGV doivent naviguer de manière autonome dans des espaces encombrés, dynamiques, avec des contraintes temps réel strictes et un bilan énergétique maîtrisé.
Ce projet développe un jumeau numérique 3D complet simulant l'intégralité de ce contexte : planification par A*, replanification dynamique face aux obstructions, gestion de missions séquentielles et supervision énergétique — 100% WebGL, sans infrastructure serveur.

Glossaire Technique — 9 Termes Clés
AGV — Automated Guided Vehicle
Robot mobile industriel autonome assurant le transport sans opérateur embarqué.
Occupancy Grid (Grille d'Occupation)
Matrice 2D : 0 libre, 1 obstacle statique, 2 barrière dynamique (24×16, 384 cellules).
Algorithme A* (A-Star)
Routage optimal via f(n)=g(n)+h(n) alliant coût réel cumulé et heuristique orientée.
Heuristique de Manhattan
Distance en 4 directions : h(n)=(|dx|+|dz|)×1.001. Accélère la recherche de ~15%.
Replanning Dynamique
Recalcul en cours de route depuis la cellule actuelle. Délai mesuré : 0.20–0.30ms.
Open Set / Closed Set
Open Set : MinHeap en O(log N). Closed Set : Set() JavaScript en O(1).
Waypoints
Points 3D (x, z) extraits du chemin A* et suivis séquentiellement par l'AGV.
Digital Twin — Jumeau Numérique
Réplique 3D fidèle synchronisée en direct avec la cinématique, les capteurs et l'énergie.
FSM MissionManager
Automate d'états : IDLE → PICKUP(A) → DELIVER_B → DELIVER_C → RECHARGE(D).

PAGE 07 — Cœur Algorithmique : A*, Replanning Dynamique & Modèle Énergétique
SMART AGV TWIN · Imad Abail
f(n)=g(n)+h(n) · MinHeap O(log N) · Replanning 0.20–0.30ms
Formalisme Mathématique — Algorithme A*
f(n) = g(n) + h(n)
f(n)
Coût estimé total
g(n)
Coût réel depuis départ
h(n)
Heuristique vers cible
h(n) = (|dx| + |dz|) × 1.001 — Manhattan Tie-Breaking (−15% nœuds)
Le facteur ×1.001 brise les égalités entre chemins de même coût f, forçant A* à privilégier le chemin le plus direct vers le but et accélérant la recherche sur grille uniforme.
Structure de Données — MinHeap & Closed Set
// Open Set : Tas binaire min — O(log N) par pop/push
openSet = new MinHeap()   // trié par f(n) croissant
closedSet = new Set()    // lookup O(1) via clé "col,row"
while openSet.size > 0:
  current = openSet.pop()
  if current == goal: return reconstructPath()
  for neighbor in 4-directions:
    if walkable AND not in closedSet:
      g_new = g(current) + 1
      h_new = manhattan(neighbor, goal) × 1.001
      openSet.push(neighbor, g_new + h_new)
Modèle de Consommation Énergétique
batterie(t) = 100 − (distance_parcourue × 0.25%/m)
Seuil critique : Batterie <20% → déclenchement RECHARGE_NEEDED → reroutage Zone D.
Mesure cycle complet A→B→C→D : Batterie = 86.8%, Odomètre = 52.9m, Temps = 00:25.
Procédure de Replanning Dynamique — 6 Étapes
1
Détection Obstacle (LiDAR)
LiDAR frontal détecte objet à distance <1.40m. Cellule obstruée : {colX, rowZ}.
2
Arrêt Immédiat — ISO 3691-4
triggerEmergencyStop() → AGV stoppé dans le cycle d'animation. Gyrophare rouge #C62828.
3
Injection Obstacle dans la Grille
grid.setObstacle(colX, rowZ, true) → mise à jour matrice grid[row][col]=1.
4
Position Courante → Cellule Départ
worldToGrid(agv.position.x, agv.position.z) = point de départ du recalcul A*.
5
Recalcul A* — 0.20 à 0.30ms
AStarPlanner génère le contournement : 11 cases (16.5m) en 0.20ms ou 14 cases en 0.30ms.
6
Reprise Navigation
agv.setPath(newPath) → animation reprend. Si fermé → affichage "0 solution A*".

Conclusion Technique
Le projet SMART AGV TWIN démontre qu'un jumeau numérique 3D d'un AGV industriel est pleinement réalisable et performant avec une architecture WebGL légère (Three.js r165 + JavaScript ES6+ natif), sans infrastructure serveur ni dépendance NPM lourde.
6 Contributions Majeures Validées
✓
Planification A* optimale : MinHeap binaire et heuristique Manhattan tie-breaking en JavaScript pur (calcul en 0.10ms).
✓
Replanification temps réel : Recalcul immédiat en 0.20–0.30ms dès détection d'obstacle sans téléportation du robot.
✓
Sécurité réflexe ISO 3691-4 : Coupure moteur instantanée sur faisceau LiDAR frontal 1.40m et gyrophare rouge.
✓
Superviseur de mission FSM : Enchaînement autonome des 4 étapes A→B→C→D avec bilan de 52.9m en 25 secondes.
✓
Rendu WebGL 3D fluide : 60 FPS constant avec 44 objets 3D, sol damier, racks et labels flottants.
✓
Architecture modulaire : 10 LABs indépendants, testables et maintenables sans compilation.
Perspectives d'Extension
Ext. 1 — Flotte Multi-AGV & Algorithme CBS
Coordination de N AGVs simultanés via l'algorithme Conflict-Based Search (CBS) avec réservation spatio-temporelle de cellules (x, y, t) pour éliminer tout risque de collision ou deadlock.
Ext. 2 — Déplacements Diagonaux 8-Directions
Génération de trajectoires lissées avec heuristique euclidienne et gestion des angles de braquage (corner-cutting prevention) pour réduire la distance parcourue de ~15%.
Ext. 3 — Interfaçage Robotique Réel ROS2
Passerelle WebSocket bidirectionnelle via le protocole standard rosbridge v2 pour transmettre les waypoints A* vers la pile de navigation ROS2 Nav2 d'un AGV physique.
Ext. 4 — Modèle Énergétique Li-ion Réaliste
Modélisation de batterie par loi de Peukert intégrant l'accélération différentielle, la masse de la charge transportée et les profils de recharge par induction.
Ext. 5 — Visualisation Immersive WebXR
Exploitation des capacités WebXR natives de Three.js pour projeter le jumeau numérique dans un casque de réalité mixte (Meta Quest) ou sur tablette en réalité augmentée.
